# Quiz / Викторины

Статический русскоязычный сайт викторин на HTML, CSS, JavaScript и JSON. Контент редактируется через Pages CMS, проверяется Python-скриптом без сторонних зависимостей и автоматически публикуется в GitHub Pages через GitHub Actions. Ветка `main` содержит исходники сайта и контента, а `gh-pages` — только готовую сборку.

## Как устроена публикация

Каждый тег хранится в `data/tags/<slug>.json`, каждая викторина — в `data/quizzes/<slug>.json`. Ручного списка файлов нет.

При изменении ветки `main` workflow `.github/workflows/pages.yml`:

1. проверяет контент командой `python tools/build_site.py --check`;
2. собирает сайт командой `python tools/build_site.py` в `_site`;
3. сканирует JSON тегов и викторин и создаёт `_site/data/catalog.json` только с опубликованными викторинами;
4. добавляет в сборку `.nojekyll`;
5. создаёт из содержимого `_site` отдельный Git-репозиторий;
6. полностью заменяет ветку `gh-pages` новой готовой сборкой.

Если проверка или сборка не проходит либо в каталоге нет опубликованной викторины `horse-colors`, ветка `gh-pages` не обновляется. В `main` папка `_site` не коммитится. Ручной список JSON-файлов не используется: сборщик обнаруживает контент автоматически.

## Структура

```text
index.html                     главная
quizzes.html                   каталог
quiz.html                      прохождение и результат
contacts.html                  контакты
css/style.css                  стили
js/common.js                   меню и общие функции
js/quizzes.js                  теги, сортировка, URL и пагинация
js/quiz.js                     прохождение, прогресс и результат
data/tags/*.json               теги
data/quizzes/*.json            полные викторины
img/covers/                    обложки
img/quiz/<quiz-slug>/          изображения вопросов отдельной викторины
tools/build_site.py            проверка и сборка
examples/quiz-template.json    пример, не попадающий в каталог
.pages.yml                     форма Pages CMS
.github/workflows/pages.yml    публикация GitHub Pages
```

## Подключение Pages CMS

1. Откройте [app.pagescms.org](https://app.pagescms.org/) и войдите через GitHub.
2. Установите GitHub App Pages CMS и разрешите доступ к `tssrkt/quiz`.
3. Выберите репозиторий и ветку `main`.
4. Pages CMS прочитает `.pages.yml` и покажет коллекции «Теги» и «Викторины».

### Английские версии обычных викторин

Для перевода не нужен API-ключ: репозиторий и GitHub Actions не обращаются к OpenAI API. Сам перевод выполняется
вручную в ChatGPT Plus, а workflow отвечает только за подготовку структуры, проверку и импорт результата.

1. В записи русской викторины запустите действие «Подготовить английскую версию».
2. Workflow создаст неопубликованный черновик `data/english-quizzes/<slug>-en.json` и пакет
   `data/translation-packages/<slug>-en.json`. При повторном запуске в пакет попадут только изменённые тексты;
   изображения, порядок, правильные ответы, теги и другие нетекстовые поля синхронизируются автоматически.
3. Откройте пакет в коллекции «Пакеты английского перевода», скачайте его или скопируйте целиком и передайте
   ChatGPT. Для ChatGPT используйте такую инструкцию:

```text
Переведи только текстовые значения этого JSON на естественный английский язык. Не изменяй структуру, ключи, ID, порядок элементов, slug, технические поля и формат JSON. Не добавляй и не удаляй элементы. Не переводи теги и технические значения. Используй принятую английскую конную, ветеринарную и генетическую терминологию. Сохрани смысл вопросов и правильность ответов. Верни только полностью валидный JSON без комментариев, пояснений и Markdown.
```

Та же инструкция находится в поле `translation_instructions` пакета; импорт игнорирует значение этого поля.
4. Полученный корректный JSON целиком вставьте вместо содержимого той же записи пакета в Pages CMS и сохраните.
   Нельзя менять структуру, ключи, ID или порядок элементов.
5. В записи пакета запустите действие «Импортировать перевод». Workflow сначала полностью проверит пакет и
   ревизию оригинала, а затем одним шагом вставит только перечисленные переводы. При любой ошибке английский JSON
   останется без изменений, а активный пакет останется на прежнем месте для исправления и повторного запуска.
6. Проверьте результат в коллекции «Английские викторины» и опубликуйте его вручную.

Неизменённые английские поля, включая ручные редакторские правки, повторная синхронизация не перезаписывает.
Если русский оригинал изменился после создания пакета, импорт отклонит устаревшую ревизию: снова выполните
«Подготовить английскую версию», переведите новый точечный пакет и импортируйте его. Успешно применённый пакет
получает статус `imported` и переносится из активного каталога в
`data/translation-packages/imported/<slug>-en.<revision>.json`. Архив исключён из активной коллекции Pages CMS,
а скрипт отклоняет прямой запуск с архивным путём, поэтому такой пакет нельзя импортировать повторно. Режим работы,
старый и новый пути пакета, а также перечни изменений выводятся в summary соответствующего workflow.

CMS сохраняет изменения непосредственно в GitHub, создавая коммиты. После изменения `main` GitHub Actions автоматически проверит и соберёт сайт. Новая корректная опубликованная викторина появится в каталоге без редактирования JavaScript, HTML или списка файлов.

## Создание тега

1. В Pages CMS откройте «Теги» и нажмите создание записи.
2. Заполните название и уникальный `slug` строчными латинскими буквами, цифрами и дефисами.
3. Укажите целый неотрицательный порядок отображения.
4. Включите «Опубликован», если тег должен появиться в каталоге.
5. Сохраните запись. Имя файла автоматически формируется как `<slug>.json`.

## Создание викторины

1. Создайте запись в коллекции «Викторины».
2. Заполните название, уникальный `slug`, дату, краткое описание и вступление. Выберите обязательный уровень сложности: «Низкая», «Средняя» или «Высокая» (в JSON сохраняются `low`, `medium` и `high`; значение по умолчанию — `low`).
3. Оставьте «Опубликована» выключенным, пока это черновик.
4. Выберите один или несколько тегов из коллекции тегов.
5. При необходимости выберите или загрузите квадратную обложку. Она сохраняется в `img/covers`. После CMS-сохранения `scripts/organize_quiz_media.py` сравнивает ссылки с предыдущим Git-состоянием и удаляет заменённый или убранный файл, только если на полный путь больше не ссылается ни одна викторина. Свежие загрузки без сохранённого JSON не считаются кандидатами на удаление. Если JSON ссылается на ранее удалённую обложку, скрипт восстанавливает файл с точным именем и регистром из истории Git.
6. Добавьте вопросы. Их можно удалять и переставлять в повторяющемся списке.
7. При необходимости заполните общий alt для изображений вопросов, затем выберите существующие файлы либо загрузите новые. Один `questionImagesAlt` применяется ко всем изображениям вопросов викторины; без него используется безопасный резервный текст. Исходные изображения текущей викторины хранятся в `img/quiz/<quiz-slug>/`; сборщик нормализует публикуемые пути по slug и позиции вопроса.
8. Добавьте от 2 до 6 вариантов. Варианты можно удалять и переставлять.
9. Для каждого варианта заполните текст. Служебные ID скрыты в Pages CMS и вручную не вводятся.
10. Включите флаг «Правильный ответ» ровно у одного варианта вопроса.
11. Заполните объяснение и при необходимости сведения об источнике.
12. Сохраните викторину и проверьте запуск workflow во вкладке **Actions** репозитория.

Pages CMS использует статический общий media-root `img/quiz` и не подставляет slug записи в путь загрузки. Поэтому сборщик копирует только используемые файлы в `img/quiz/<quiz-slug>/` готового сайта и присваивает им позиционные имена, не смешивая изображения разных викторин и не публикуя дубли.

Служебные ID хранятся непосредственно в `data/quizzes/*.json`. Вопросы получают `question-01`, `question-02` и далее, ответы — `answer-01`, `answer-02` и далее внутри каждого вопроса. После CMS-коммита workflow дописывает только отсутствующие ID отдельным идемпотентным шагом. Существующие ID сохраняются при редактировании текста, перестановке и удалении соседних элементов.

## Формат ответа

Правильный ответ хранится в вопросе как стабильный ID варианта, поэтому изменение порядка не повреждает выбор:

```json
{
  "id": "question-01",
  "question": "Текст вопроса",
  "image": "img/quiz/quiz-example/01.webp",
  "correct_answer_id": "answer-02",
  "answers": [
    {"id": "answer-01", "text": "Первый вариант"},
    {"id": "answer-02", "text": "Правильный вариант"}
  ],
  "explanation": "Почему этот ответ правильный.",
  "image_source": "",
  "image_author": "",
  "image_source_url": ""
}
```

Pages CMS требует выбрать одно значение `correct_answer_id`. Сборщик также принимает старые данные с одним `correct: true`, преобразует их в новый формат и удаляет флажки из публикуемых данных. Полный образец находится в `examples/quiz-template.json` и не сканируется сборщиком.

## Черновики и предварительный просмотр

Черновик с `published: false` не включается в каталог и без специального параметра не запускается. После успешной сборки его можно открыть напрямую:

```text
https://tssrkt.github.io/quiz/quiz.html?quiz=my-quiz&preview=1
```

Локально адрес выглядит так:

```text
http://localhost:8000/quiz.html?quiz=my-quiz&preview=1
```

На странице показывается предупреждение «Предварительный просмотр. Викторина не опубликована». Для публикации включите поле «Опубликована» и сохраните запись.

`preview=1` — не защита приватных материалов. Полный JSON черновика находится среди статических файлов и доступен технически подготовленному посетителю.

## Прохождение и сохранение прогресса

Движок сохраняет попытку отдельно для каждого slug в `localStorage`. Сохранение содержит версию формата, сигнатуру вопросов и вариантов, текущую позицию, выбранные ответы, их правильность, количество правильных ответов, дату и признак завершения. Если вопросы или варианты изменились, несовместимое сохранение автоматически сбрасывается.

Правильный ответ блокирует варианты и автоматически переводит дальше через 800 мс. Неправильный ответ показывает правильный вариант, объяснение и кнопку перехода. Анимация конфетти встроена локально и отключается при `prefers-reduced-motion`.

На итоговом экране доступны Web Share, Telegram, ВКонтакте и копирование результата. Публикуемая ссылка ведёт непосредственно на викторину и не содержит `preview` или данных прогресса.

## Локальная проверка и запуск

Статические страницы индивидуальных превью создаются командой:

```bat
python scripts/generate_share_pages.py
```

Генератор берёт `slug`, название (`title`), описание (`short_description`) и обложку (`cover`) непосредственно из `data/quizzes/*.json` и создаёт страницы только для опубликованных викторин. Запускайте его после добавления викторины или изменения этих полей, затем коммитьте обновлённый каталог `v/`. Обычная сборка `python tools/build_site.py` также создаёт эти страницы в `_site/v/`.

Только проверить контент:

```bat
python tools/build_site.py --check
```

Собрать и запустить:

```bat
python tools/build_site.py
python -m http.server 8000 -d _site
```

Откройте `http://localhost:8000/`. Прямое открытие через `file://` не поддерживается, поскольку браузеры ненадёжно разрешают загрузку JSON в таком режиме.

Автоматические тесты:

```bat
python -m unittest tests.test_build_site
python -m unittest tests.test_share_pages
node tests/catalog.test.js
node tests/quiz.test.js
```

При наличии Python Playwright и Chrome три полных браузерных сценария запускаются командой:

```bat
python tests/ui_quiz_scenarios.py
```

## Что проверяет сборщик

- обязательные поля и формат slug;
- уникальность slug викторин и тегов;
- уникальность названий тегов без учёта регистра;
- совпадение slug с именем JSON-файла;
- дату публикации;
- существование используемых тегов;
- заполненность, формат и уникальность сохранённых ID вопросов;
- от 2 до 6 вариантов, формат и уникальность сохранённых ID ответов внутри вопроса;
- ровно один правильный вариант;
- обязательное объяснение;
- относительные пути обложек и изображений;
- существование локальных изображений;
- внешние ссылки источников с `http://` или `https://`.

Ошибки выводятся с именем файла и путём проблемного поля. Сборка завершается ненулевым кодом.

## Публикация GitHub Pages

Workflow использует разрешение `contents: write`, чтобы стандартным `GITHUB_TOKEN` принудительно обновлять только ветку `gh-pages`. Он запускается при push только в `main` или вручную, поэтому создаваемый им push в `gh-pages` не запускает новую публикацию. Исходники остаются в `main`, а HTML, CSS, JavaScript, изображения и сгенерированные данные из `_site` публикуются в корень `gh-pages`.

## Ограничения

- Pages CMS не может гарантировать условие «ровно один правильный ответ» внутри формы; это строго проверяет сборщик до публикации.
- Предпросмотр черновика публичен по своей природе.
- Прогресс хранится только в `localStorage` текущего браузера и устройства.
## Словарные викторины

Словарная викторина хранится как отдельный тип контента и ссылается на таблицу вместо массива `questions`:

```json
{
  "type": "vocabulary",
  "table": "../vocabulary/example.xlsx"
}
```

Сборщик читает первый лист `.xlsx` (также поддерживается Excel-совместимый UTF-8 CSV) со столбцами `English`, `Russian`, `Category`. Первые два столбца обязательны, категория может быть пустой. Строки импортируются командой `python tools/build_site.py`; в итоговый JSON записывается компактный массив `vocabulary`, а вопросы EN → RU создаются в браузере при начале прохождения.
